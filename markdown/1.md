### 第一份代码：无限接近正解，但注定 TLE (超时)

**选手的思考过程：**
“我已经推导出了发钱模型！要验证 $k$ 步够不够，我只需要发 $k$ 次钱，每次把当前面值 $2^b$ 发给需求最大的人就行了。既然需要找最大值，那就写个 `for` 循环遍历一遍数组找呗！反正只找 $k$ 次，应该挺快的！”

**为什么它能过样例？**
因为它的数学逻辑是 $100\%$ 正确的，贪心策略也是完美的。由于样例的 $N$ 最大只有 $6$，$k$ 也只有 $6$，这种 $O(N)$ 找最大值的方式在小数据下飞快，运行结果和正解一模一样。

**为什么它会 TLE？**
选手产生了一个致命的错觉：“$k$ 应该很小吧？”。
实际上，最坏情况下 $k \approx N + 30$。单次 `check` 内部有一个循环 $k$ 次的外层，和一个遍历 $N$ 找最大值的内层。
单次 `check` 复杂度是 $O(K \cdot N) \approx O(N^2)$。加上二分，总复杂度是 $O(N^2 \log N)$。
当 $N = 2 \cdot 10^5$ 时，$N^2 = 4 \cdot 10^{10}$，直接卡死在测试点 2 或 3。

```cpp
// 接近正确但会 TLE 的代码 (O(N)暴力找最大值)
#include<bits/stdc++.h>
using namespace std;

using i32 = int;
using i64 = long long;

int T = 1;

bool check(int k, vector<i32> a) {
    // 发 k 张钞票
    for (int b = k - 1; b >= 0; --b) {
        // 致命操作：不用优先队列，每次 O(N) 暴力找当前最大值
        int max_idx = 0;
        for (int i = 1; i < a.size(); ++i) {
            if (a[i] > a[max_idx]) {
                max_idx = i;
            }
        }
      
        if (a[max_idx] <= 0) return true; // 所有人都吃饱了
      
        // 防溢出是对的
        if (b <= 30) {
            a[max_idx] -= (1 << b);
        } else {
            a[max_idx] = 0; 
        }
    }
  
    for (int x : a) {
        if (x > 0) return false;
    }
    return true;
}

void solve() {
    int n;
    cin >> n;
    vector<i32> a(n);
    for (int i = 0; i < n; ++i) cin >> a[i];
  
    int L = 1, R = n + 32;
    int ans = R;
    while (L <= R) {
        int mid = L + (R - L) / 2;
        if (check(mid, a)) {
            ans = mid;
            R = mid - 1;
        } else {
            L = mid + 1;
        }
    }
    cout << ans << "\n";
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    for(cin >> T; T--; solve());
    return 0;
}
```

### 第二份代码：算法完全正确，但注定 WA (答案错误)

**选手的思考过程：**
选手经历了刚才的 TLE，顿悟了：“啊！每次找最大值必须用 `priority_queue` 优化到 $O(\log N)$！”
于是他飞快地改好了优先队列。但在处理钞票面值 $2^b$ 时，他没有用 `if (b <= 30)` 截断，而是自信地写下了 `i64 coin = 1LL << b;`。
选手心想：“我用了 `long long`（64位整数），区区 $2^b$ 怎么可能溢出呢？”

**为什么它能过样例？**
观察题目给的样例，最大的答案是 $6$。这意味着在二分和 `check` 的过程中，$b$ 最大也只达到了 $5$。
`1LL << 5` 等于 $32$，在 `long long` 的承受范围内，完美计算，毫无压力。样例全部畅通无阻地 AC！

**为什么它会 WA？**
当数据达到 $N = 2 \cdot 10^5$ 时，二分会去检查 $k = 100,000$ 这样的巨大步数。此时 $b$ 也会高达 $99,999$。
在 C++ 中，**对一个 64位整数进行大于等于 64 位的左移是未定义行为（UB）**。
在现代 X86 架构下，`1LL << b` 会把 `b` 对 64 取模！
也就是说，当 $b = 64$ 时，`1LL << 64` 会变成 `1LL << 0 = 1`。
这意味着：本该是一张面值爆表的“超级大钞票”，由于位移溢出，被系统变成了一张面值仅为 `1` 的假钞！它根本无法清零原本的需求，导致 `check` 函数本该返回 `true` 却返回了 `false`。
最终，二分法会给出极其离谱的错误答案。

```cpp
// 算法正确但会 WA 的代码 (C++左移未定义行为陷阱)
#include<bits/stdc++.h>
using namespace std;

using i32 = int;
using i64 = long long;

int T = 1;

bool check(int k, const vector<i32>& a) {
    priority_queue<i64> pq;
    for (i32 x : a) {
        if (x > 0) pq.push(x);
    }
  
    for (int b = k - 1; b >= 0; --b) {
        if (pq.empty()) return true;
      
        i64 x = pq.top();
        pq.pop();
      
        // 致命错误：没有考虑 b >= 64 时的 UB (未定义行为)
        // 当 b = 64 时，b % 64 = 0，coin 变成了 1！
        i64 coin = (1LL << b); 
      
        x -= coin;
        if (x > 0) {
            pq.push(x);
        }
    }
    return pq.empty();
}

void solve() {
    int n;
    cin >> n;
    vector<i32> a(n);
    for (int i = 0; i < n; ++i) cin >> a[i];
  
    int L = 1, R = n + 32;
    int ans = R;
    while (L <= R) {
        int mid = L + (R - L) / 2;
        if (check(mid, a)) {
            ans = mid;
            R = mid - 1;
        } else {
            L = mid + 1;
        }
    }
    cout << ans << "\n";
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    for(cin >> T; T--; solve());
    return 0;
}
```

=======
这道题的核心是一个非常有趣的**依赖与死锁模型**。我们可以把它转化为一个极简的贪心问题。

### 💡 核心思路：将三元关系转化为“拓扑消除”

我们手上有两个名单 $P$ 和 $Q$。每次比赛相当于在这两个名单中“同时暴露”它们**当前尚未被淘汰的第一个选手**，设为 $u$ 和 $v$。
1. **死锁条件**：如果 $u = v$，代表两个人是同一个人，比赛无法进行，发生死锁。
2. **正常推进**：如果 $u \neq v$，我们可以选择淘汰 $u$ 或淘汰 $v$。淘汰意味着将这个人从**所有**后续的比赛名单中抹去。
3. **目标**：让指定的选手 $x$ 活到最后，这意味着他绝对不能被淘汰；我们必须淘汰其余的 $n-1$ 个选手。

**关键破局点（Diamond Property / 汇合性）**：
在任意时刻，如果淘汰 $u$ 和淘汰 $v$ 都不导致“立即死锁”（即淘汰后，两个名单新暴露出的头部不一样），那么**随便选哪一个淘汰最终都能赢**（前提是这局本身能赢）。如果某个选择看起来合法，但最终导致了无解，那么另一个选择也必然无解！
所以，我们**完全不需要 DFS 回溯**，只需要做一个极致简单的**安全贪心策略**：

* 如果当前是 $u$ 和 $v$：
  * **尝试淘汰 $u$ 是否安全？**：我们预判一下，如果淘汰了 $u$，$P$ 名单的下一个待定选手（`next_P`）会不会恰好等于 $v$？如果等于 $v$，那下一步就会暴露两个 $v$，导致立马死锁！所以此时**不能淘汰 $u$**（唯一的例外是：`next_P` 和 $v$ 都是我们希望的最终冠军 $x$，且这是最后一场淘汰赛，这时候碰撞不仅合法，而且代表我们赢了）。
  * **尝试淘汰 $v$ 是否安全？**：同理，如果淘汰了 $v$，$Q$ 名单的下一个待定选手（`next_Q`）会不会恰好等于 $u$？如果是，也**不能淘汰 $v$**。
* 每一步只要选出**任意一个安全的选择**执行即可。如果两个都不安全，直接判定为无解 `NO`。

### 🚀 O(N) 极速代码实现

为了极致高效，我们只需维护 $4$ 个单调递增的指针，分别指向 $P$ 和 $Q$ 的“当前头”和“下一个头”，指针只会前进不会后退，整体时间复杂度为严格的 $O(N)$。

```cpp
#include <iostream>
#include <vector>

using namespace std;

void solve() {
    int n, x;
    if (!(cin >> n >> x)) return;
  
    vector<int> P(n + 1), Q(n + 1);
    for (int i = 1; i <= n; i++) cin >> P[i];
    for (int i = 1; i <= n; i++) cin >> Q[i];
  
    // 记录某个选手是否已经被淘汰
    vector<bool> in_S(n + 1, false);
  
    // p1, q1 指向各自名单的当前头部; p2, q2 指向各自名单的"下一个"头部
    int p1 = 1, p2 = 2;
    int q1 = 1, q2 = 2;
  
    // 推进 P 名单的指针，跳过所有已经被淘汰的人
    auto advance_P = [&]() {
        while (p1 <= n && in_S[P[p1]]) p1++;
        if (p2 <= p1) p2 = p1 + 1;
        while (p2 <= n && in_S[P[p2]]) p2++;
    };
  
    // 推进 Q 名单的指针，跳过所有已经被淘汰的人
    auto advance_Q = [&]() {
        while (q1 <= n && in_S[Q[q1]]) q1++;
        if (q2 <= q1) q2 = q1 + 1;
        while (q2 <= n && in_S[Q[q2]]) q2++;
    };
  
    advance_P();
    advance_Q();
  
    vector<int> ans;
    ans.reserve(n);
  
    // 我们必须淘汰恰好 n-1 个人
    while (ans.size() < n - 1) {
        if (p1 > n || q1 > n) {
            cout << "NO\n";
            return;
        }
      
        int u = P[p1];
        int v = Q[q1];
      
        // 发现当前两人是同一个人，出现死锁
        if (u == v) {
            cout << "NO\n";
            return;
        }
      
        // 1. 评估淘汰 u 是否安全？
        bool valid_u = false;
        if (u != x) { // 绝不能淘汰最终赢家 x
            int next_P_val = (p2 <= n) ? P[p2] : -1;
            if (next_P_val == v) { // 淘汰后会不会立马撞脸？
                // 如果撞脸的是 x 且这是最后一步，那是可以的（直接胜利）
                if (v == x && ans.size() == n - 2) valid_u = true; 
            } else {
                valid_u = true;
            }
        }
      
        // 2. 评估淘汰 v 是否安全？
        bool valid_v = false;
        if (v != x) {
            int next_Q_val = (q2 <= n) ? Q[q2] : -1;
            if (next_Q_val == u) {
                if (u == x && ans.size() == n - 2) valid_v = true;
            } else {
                valid_v = true;
            }
        }
      
        // 3. 贪心决策：哪边安全就淘汰哪边
        if (valid_u) {
            ans.push_back(u);
            in_S[u] = true;
        } else if (valid_v) {
            ans.push_back(v);
            in_S[v] = true;
        } else {
            // 两边都不安全，陷入必定死锁的局面
            cout << "NO\n";
            return;
        }
      
        // 更新指针状态
        advance_P();
        advance_Q();
    }
  
    // 如果成功活过了 n-1 轮淘汰，打印答案
    cout << "YES\n";
    for (int i = 0; i < n - 1; i++) {
        cout << ans[i] << (i == n - 2 ? "" : " ");
    }
    cout << "\n";
}

int main() {
    // 优化 I/O 加速读取
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);
    solve();
    return 0;
}
```
