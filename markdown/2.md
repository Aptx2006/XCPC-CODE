这是一道极其优美且富有深度的“思维与转换”题。表面上看是在模拟除以 $2$ 的过程，但只要我们把它转入“二进制”的视角，整个看似混沌的操作就会立刻豁然开朗，变成一个纯粹的“贪心分配资源”问题。

以下是我在草稿纸上的推导全过程和最终题解。

### 💡 核心推演：把除法变成加法

**第一步：拆解操作的数学本质**
一次操作会对选中的数向下取整，对其他数向上取整。
- 向下取整：$\lfloor \frac{x}{2} \rfloor$
- 向上取整：$\lceil \frac{x}{2} \rceil = \lfloor \frac{x + 1}{2} \rfloor$

如果在连续的 $k$ 次操作中，对于某个元素 $x$，我们在第 $j$ 次（从后往前数， $j=1,2,\dots,k$）没有选择它（即加上了 $1$），那么 $k$ 次操作后它的值会变成多少呢？
通过简单的数学归纳法展开，最终它的值会变成：
$$ x_k = \left\lfloor \frac{x + \sum c_j 2^{j-1}}{2^k} \right\rfloor $$
其中，$c_j = 0$ 表示在第 $j$ 步选中了它；$c_j = 1$ 表示没选中它。

我们要让 $x$ 最终变成 $0$，就等价于：
$$ x + \sum c_j 2^{j-1} < 2^k \implies \sum c_j 2^{j-1} \le 2^k - 1 - x $$

**第二步：发现隐藏的“零和博弈”**
上面公式里的 $\sum c_j 2^{j-1}$ 其实就是用 $c_j$ 拼成的一个二进制数 $V$。
由于在每一步中，**必定有且仅有一个元素被选中（即 $c_j=0$）**，这意味着在所有的 $n$ 个元素中，它们第 $j$ 位的 $c$ 值必定是 **1个 $0$ 和 $n-1$ 个 $1$**。
换句话说，如果我们将 $V_i$ 取个反，令 $W_i = (2^k - 1) - V_i$，那么 $W_i$ 拼成的所有二进制位绝对是**互不重叠（两两相交为空）的**！
原不等式 $V_i \le 2^k - 1 - a_i$ 就完美地转化为了：
$$ W_i \ge a_i $$

**总结惊天结论：**
进行 $k$ 次操作并让所有数归零，等价于：
**我们手里有互不相交的 $k$ 张“钞票”，面值分别是 $2^0, 2^1, \dots, 2^{k-1}$。现在要把这些钞票分给 $n$ 个人，使得第 $i$ 个人拿到的面值总和 $\ge a_i$。问最少需要多少张连号钞票（求最小的 $k$）。**

### 🧠 贪心判定（check函数）

如果给定了总钞票数 $k$，我们怎么判断钱够不够分呢？
因为所有的钞票都是 $2$ 的幂次，这有一个绝妙的贪心策略：**好钢用在刀刃上，最大的钱一定要塞给当下胃口最大（剩余需求最高）的人！**

我们把要求降序排列（借助大根堆 priority_queue）：
1. 取出面值最大的钞票 $2^b$（从 $b = k-1$ 倒序遍历到 $0$）。
2. 从堆顶弹出当前最大的需求量 $x$。
3. 把 $2^b$ 塞给他！他剩余的需求量变成 $\max(0, x - 2^b)$。
4. 如果他还有需求没被填满，就把新的剩余值重新扔回大根堆里。
5. 遍历完所有 $k$ 张钞票后，如果大根堆空了（所有人的需求都降到了 $0$），说明 $k$ 次操作绝对够用！否则不够用。

### 🚀 XCPC 模板代码与极端优化

**时间复杂度优化：**
因为 $a_i \le 10^9 < 2^{30}$，如果当前的钞票面值 $2^b$ 对应的 $b \ge 30$，那么这张钞票给任何一个人都会瞬间把他的需求“撑爆”（彻底满足降为 $0$）。所以对于 $b \ge 30$ 的情况，我们直接从堆里弹出最大值丢掉即可，连减法运算都省了！这就意味着 `check` 函数内部堆积操作最多执行 $n+30$ 次。时间飞快，毫无压力。

我们直接在可能区间 $[1, n+32]$ 之间对 $k$ 跑二分答案即可。

```cpp
#include<bits/stdc++.h>
using namespace std;

using i32 = int;
using i64 = long long;
using i128 = __int128;
#define all(x) (x).begin(), (x).end()
#define dbg(x) cerr << #x << " = " << (x) << endl;

int T = 1;

// 验证 k 步是否能把所有元素变成 0
bool check(int k, const vector<i32>& a) {
    priority_queue<i32> pq;
    // 把所有 >0 的初始需求放入大根堆
    for (i32 x : a) {
        if (x > 0) pq.push(x);
    }
  
    // 从最大的钞票开始贪心发钱
    for (int b = k - 1; b >= 0; --b) {
        if (pq.empty()) return true; // 所有人都吃饱了
      
        i32 x = pq.top();
        pq.pop();
      
        // 当 b >= 30 时，2^b 已经大于 10^9，直接秒杀当前最大值 x
        // 只有 b <= 30 的时候我们才需要真刀真枪地扣减并放回堆中
        if (b <= 30) {
            x -= (1 << b);
            if (x > 0) {
                pq.push(x);
            }
        }
    }
    return pq.empty(); // 如果堆空了，代表全归0，操作可行
}

void solve() {
    int n;
    cin >> n;
    vector<i32> a(n);
    for (int i = 0; i < n; ++i) {
        cin >> a[i];
    }
  
    // 最坏情况下，如果每个人都嗷嗷待哺需要很大的面值
    // 最多只需要分配完最大的 n 张钞票(对应上限 n + 32)
    int L = 1, R = n + 32;
    int ans = R;
    while (L <= R) {
        int mid = L + (R - L) / 2;
        if (check(mid, a)) {
            ans = mid;    // mid 步可行，记录答案并尝试找更小的
            R = mid - 1;
        } else {
            L = mid + 1;  // mid 步不可行，必须加步数
        }
    }
    cout << ans << "\n";
}

int main() {
    // 关流提升 cin cout 性能，XCPC必加黑箱
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    for(cin >> T; T--; solve());
    return 0;
}
```

### 通俗题解总结
把繁琐的全局位移规则转换成**“用相互无交集的 $2$ 的幂次拼凑出目标值”**。一旦思维从“数组模拟”跃迁至“发工资模型”，这就成了一道再简单不过的贪心+二分了。巧妙规避越界的 `if(b <= 30)` 也是在 XCPC 考场上保证不爆数据类型的实战常识。
