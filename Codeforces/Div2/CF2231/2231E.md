

# 题目大意

给一棵 \(n\) 个点的树，和一个整数 \(d\)。

要统计有多少个**无序三元组** \((a,b,c)\)（三个点互不相同），满足：

- 这三个点在树上的**最小连通子树**恰好包含 **\(d\) 个点**。

---

## 等价转化

树上一个连通子树如果有 \(d\) 个点，那么它有 \(d-1\) 条边。

所以题意也等价于：

- 统计有多少组三个点，它们的最小连通子树的边数恰好为 \(d-1\)。

因此代码里一开始写了：

```cpp
d--;
```

后面程序统一把问题当成：

- 三点的最小连通子树边数和为 `d`

来做。

---

# 核心观察

对于树上三个点，它们的最小连通子树只可能有两种形态：

---

## 1. 链形

三个点都在同一条简单路径上。

比如：

```text
a ---- b ---- c
```

那么最小连通子树就是一条链。

这时中间那个点是三元组中的一个点。

---

## 2. Y 形

存在一个分叉点 `rt`，三个点分别落在 `rt` 的三棵不同方向的子树里。

比如：

```text
      x
      |
      rt
     /  \
    y    z
```

这时三点到 `rt` 的距离分别是 \(x,y,z\)，并且

\[
x+y+z=d
\]

---

这两种情况，其实都可以统一到一个“**枚举中心点 rt**”的框架里解决。

---

# 思考过程

---

## 一、最暴力的想法

枚举三个点 \((a,b,c)\)，然后求它们的最小连通子树大小。

如果用点对距离来算，可以利用公式：

设三点的汇合点为 \(t\)，那么最小连通子树边数为

\[
\frac{dist(a,b)+dist(b,c)+dist(c,a)}{2}
\]

于是暴力可以：

1. 先预处理任意两点距离；
2. 枚举三元组；
3. 判断是否满足边数为 \(d-1\)。

---

### 复杂度

- 预处理距离：\(O(n^2)\) 或 \(O(n(n+m))\)
- 枚举三元组：\(O(n^3)\)

总复杂度至少 \(O(n^3)\)，很难通过。

---

## 二、换个视角：枚举“连接中心”

三个点的最小连通子树里，一定存在一个“中心结构”：

- 要么是链中间的那个点；
- 要么是 Y 形的分叉点。

所以我们可以枚举这个点 `rt`。

然后只考虑：

- 从 `rt` 出发，不同邻接子树里有多少点在不同深度上。

---

# 枚举根 `rt` 的计数方式

固定一个点 `rt`。

设 `rt` 的邻居形成若干棵“方向子树”。

对每一棵方向子树，统计：

```cpp
cnt[dep] = 这棵子树里，距离 rt 恰好为 dep 的点数
```

其中 `dep` 只统计到 `d` 即可，因为更深已经不可能参与答案。

---

## 为什么只需要不同子树的信息

因为树上经过 `rt` 的三点连通结构，必须来自：

- 两个不同方向 + `rt` 本身（链形）
- 三个不同方向（Y 形）

如果两个点落在同一棵方向子树中，它们之间的路径不会经过 `rt`，这时不能把 `rt` 当作该三元组的中心来统计。

所以“**不同子树**”这个限制非常关键。

---

# 状态设计

代码里维护了两个数组：

```cpp
vector<i64>pre1(d + 1), pre2(d + 1);
```

含义分别是：

---

## 1. `pre1[s]`

在已经处理过的若干棵子树中，距离 `rt` 恰好为 `s` 的点一共有多少个。

也就是“单点信息”。

---

## 2. `pre2[s]`

在已经处理过的若干棵子树中，选两个点，且这两个点来自**不同子树**，并且它们到 `rt` 的距离和为 `s` 的方案数。

也就是“跨子树两点信息”。

---

# 每处理一棵新子树时如何贡献答案

假设当前处理的这棵子树的深度统计为 `cnt`。

我们考虑当前子树里取一个点，深度为 `x`。

---

## 第一类贡献：链形

```cpp
res += depCnt[x] * pre1[d - x];
```

解释：

- 当前子树里取一个点，深度 `x`
- 之前处理过的子树里取一个点，深度 `d-x`
- 第三个点就是 `rt`

于是三点形成一条经过 `rt` 的链，总边数就是：

\[
x + (d-x)=d
\]

这恰好对应最小连通子树边数为 `d`。

---

### 这一类为什么能把所有链形都统计到？

因为任意一个链形三元组：

```text
u --- rt --- v
```

只要中间那个点 `rt` 是三元组中的一个点，它就会在枚举到该 `rt` 时被统计。

例如整条路径长为 `d`，选路径内部任意一个点当第三个点，它都会在某次 `rt` 枚举中被计入。

所以这一项就是在统计：

- “三元组中包含 `rt`”
- 且另外两个点分居 `rt` 两侧

的情况。

---

## 第二类贡献：Y 形

```cpp
res += depCnt[x] * pre2[d - x];
```

解释：

- 当前子树里取一个点，深度 `x`
- 之前已经有一对跨不同子树的点，它们深度和是 `d-x`

那么这三个点分别来自三棵不同子树，经过 `rt` 汇合，形成 Y 形。

总边数：

\[
x + (d-x)=d
\]

符合要求。

---

# 处理完当前子树后，如何更新状态

当前子树统计完答案后，要把它并入“之前处理过的部分”。

---

## 更新 `pre1`

这个很直接：

```cpp
pre1[x] += depCnt[x];
```

表示当前子树里所有深度为 `x` 的点，以后都可以作为“之前的单点”。

---

## 更新 `pre2`

这个是关键。

要把“当前子树里的一个点”和“之前子树里的一个点”拼成一对跨子树点。

如果当前子树取深度 `x`，之前取深度 `y`，那么新形成的两点方案会对：

```cpp
pre2[x + y]
```

产生贡献：

\[
depCnt[x]\times pre1[y]
\]

因此更新式是：

\[
pre2 += depCnt * pre1
\]

这里的 `*` 就是卷积。

---

# 为什么会想到 FFT

如果直接暴力更新 `pre2`：

```cpp
for(int x = 1; x <= d; x++) {
    for(int y = 1; y + x <= d; y++) {
        pre2[x + y] += depCnt[x] * pre1[y];
    }
}
```

那么每处理一棵子树就是 \(O(d^2)\)。

假设整棵树很多点、`d` 也很大，总复杂度会很吃紧。

---

## 卷积形式

注意到上面的转移完全符合多项式乘法：

- `depCnt[x]` 是一个系数
- `pre1[y]` 是一个系数
- 按下标和累加到 `x+y`

这就是标准卷积，所以可以用 FFT 优化为：

\[
O(d\log d)
\]

---

# FFT 优化部分

代码中这一段：

```cpp
if(ok1 && ok2) {
    vector<i64>tmp = fft.multiply(depCnt, pre1, d);
    for(int x = 0; x < (int)tmp.size(); x++) {
        pre2[x] += tmp[x];
    }
}
```

就是把：

\[
pre2 += depCnt * pre1
\]

交给 FFT 做。

其中 `lim = d`，表示我们只关心下标不超过 `d` 的部分，更大的下标不可能再对答案有贡献，可以直接截断。

---

# 为什么要“根据模板调整 FFT”

你原始的 FFT 模板是一个**单次多项式乘法模板**，适合这种用法：

1. 给定两组多项式系数；
2. 做一次 FFT；
3. 输出结果。

但本题需要在 `solve()` 中：

- 多次进行卷积；
- 每次卷积长度都可能不同；
- 每次都要清空旧数据重新使用。

所以必须对模板做一点“工程化改造”。

---

## 保留了什么

你原本 FFT 的核心都保留了：

- `struct com`
- `PI`
- `A, B, R`
- `la, lb, mi`
- `update()`
- `fun(op, ab)`

也就是**真正的 FFT 核心实现基本没动**。

---

## 新增了什么

为了让它能在题里反复调用，只补了几个必要功能：

---

### 1. 默认构造

原来构造函数需要固定传参数。

现在改成支持：

```cpp
FFT(int nn = 0, int mm = 0, int N = 1)
```

这样就可以先全局定义一个 `fft` 对象，等真正卷积时再初始化。

---

### 2. `init(nn, mm)`

作用是：

- 设置当前卷积的多项式次数；
- 调 `update()` 算出本次 `mi`；
- 保证 `A/B/R` 长度够；
- 清空本次要用到的区间。

这一步是为了“重复使用模板”。

---

### 3. `multiply(a, b, lim)`

把原来的单次流程封装起来：

1. `init`
2. 把 `a,b` 填到 `A,B`
3. 正变换
4. 点值相乘
5. 逆变换
6. 截取前 `lim+1` 项返回

这样 `solve()` 里就可以直接写：

```cpp
vector<i64>tmp = fft.multiply(depCnt, pre1, d);
```

代码会整洁很多。

---

# 代码流程总览

---

## 1. 读入树

```cpp
cin >> n >> d;
d--;
```

把题目的“子树点数为 d”转成“边数为 d-1”。

---

## 2. 枚举每个点作为中心 `rt`

```cpp
for(int rt = 1; rt <= n; rt++)
```

---

## 3. 枚举 `rt` 的每棵相邻子树

对每个邻居 `v`：

- DFS 统计这棵子树中每个深度的点数 `depCnt[dep]`

```cpp
dfs(dfs, v, rt, 1);
```

---

## 4. 用 `depCnt` 与已有信息拼答案

```cpp
res += depCnt[x] * pre1[d - x];
res += depCnt[x] * pre2[d - x];
```

分别对应：

- 链形
- Y 形

---

## 5. 用 FFT 更新 `pre2`

```cpp
tmp = fft.multiply(depCnt, pre1, d)
pre2 += tmp
```

---

## 6. 更新 `pre1`

```cpp
pre1[x] += depCnt[x];
```

# 正确性说明

下面给出比较正式的证明思路。

---

## 引理 1

任意满足条件的三元组，其最小连通子树必然可以唯一归类到某个中心点 `rt`。

### 证明

树上三个点的最小连通子树只有两种结构：

1. 一条链；
2. 一个三叉点加三条支路的 Y 形。

- 若是链，则唯一的中间点可作为中心 `rt`；
- 若是 Y 形，则唯一的分叉点可作为中心 `rt`。

因此每个三元组都能唯一归到某个 `rt`。证毕。

---

## 引理 2

固定中心 `rt` 时，代码中第一类转移

```cpp
depCnt[x] * pre1[d - x]
```

恰好统计了所有以 `rt` 为中心、且 `rt` 本身属于三元组的方案。

### 证明

- 当前子树取一点，深度 `x`
- 以前子树取一点，深度 `d-x`
- 第三个点取 `rt`

因为两点来自 `rt` 的不同方向，所以它们之间路径一定经过 `rt`，形成链形结构，边数为 `x+(d-x)=d`。

反过来，任意以 `rt` 为链中点的合法三元组，都会在处理到其中后一棵子树时被唯一统计一次。证毕。

---

## 引理 3

固定中心 `rt` 时，代码中第二类转移

```cpp
depCnt[x] * pre2[d - x]
```

恰好统计了所有以 `rt` 为中心、且三个点分居三棵不同子树的方案。

### 证明

`pre2[s]` 已经表示：从之前处理过的不同子树里选两个点，且深度和为 `s` 的方案数。

现在当前子树再取一个深度 `x` 的点，只要 `x+s=d`，三个点分别位于三棵不同子树中，它们经过 `rt` 汇合形成 Y 形，边数和为 `d`。

反过来，任意这样的 Y 形三元组，按子树处理顺序，一定会在“最后进入的那棵子树”被唯一统计。证毕。

---

## 引理 4

`pre2 += depCnt * pre1` 恰好维护了“跨不同子树的两点方案”。

### 证明

当前子树任取一个点、已处理子树任取一个点，这两点必在不同子树。

若深度分别为 `x,y`，则它们对 `pre2[x+y]` 的贡献为 `depCnt[x]*pre1[y]`。

按深度和聚合，正是卷积定义。证毕。

---

## 定理

算法最终得到的 `res` 恰好等于满足要求的无序三元组数。

### 证明

由引理 1，每个合法三元组有唯一中心 `rt`。

由引理 2 和引理 3，固定 `rt` 时，所有以 `rt` 为中心的合法三元组被完整且不重不漏统计。

对所有 `rt` 求和，即得到总答案。证毕。

---

# 时空复杂度分析

设输入树有 \(n\) 个点。

---

## 1. DFS 统计深度

对于每个 `rt`，会对它每棵方向子树做 DFS，且深度最多到 `d`。

最坏情况下，总访问量可以到 \(O(n^2)\)。

例如链状树且 `d` 很大时，很多根都会扫到很多点。

---

## 2. FFT 部分

每处理一棵子树，最多做一次长度约为 \(d\) 的卷积。

一次 FFT 复杂度是：

\[
O(d\log d)
\]

整棵树总共有 \(2(n-1)\) 次“有向邻边对应的子树处理”，因此 FFT 总复杂度约为：

\[
O(n d \log d)
\]

---

## 3. 总复杂度

综上，总复杂度可写作：

\[
O(n^2 + n d \log d)
\]

这也是这份代码比较合理的复杂度描述。

---

## 4. 空间复杂度

主要来自：

- 邻接表：\(O(n)\)
- 若干深度数组：\(O(d)\)
- FFT 工作数组：\(O(d)\)

总空间复杂度：

\[
O(n + d)
\]

更准确地说是 `FFT` 中的数组大小为不小于 `2d` 的二次幂，所以仍然是线性级别。

---

# 为什么不用纯暴力更新 `pre2`

如果不用 FFT，那么更新 `pre2` 需要：

```cpp
for(int x = 1; x <= d; x++) {
    for(int y = 1; x + y <= d; y++) {
        pre2[x + y] += depCnt[x] * pre1[y];
    }
}
```

单次 \(O(d^2)\)。

那总体会接近：

\[
O(n d^2)
\]

当 `d` 大时往往扛不住，所以这里用 FFT 做卷积优化是非常自然且必要的。

---

# 最终代码

下面就是你现在这版模板化后的完整代码：

```cpp
#include<bits/stdc++.h>
using namespace std;

using i32 = int;
using i64 = long long;
using i128 = __int128;
#define all(x) (x).begin(), (x).end()
#define dbg(x) cerr << #x << " = " << (x) << endl;

int T, n, m, k, ans, cnt;

class FFT {
public:
    struct com {
        double x, y;
        com operator+(const com&t)const{
            return {x + t.x, y + t.y};
        }
        com operator-(const com&t)const{
            return {x - t.x, y - t.y};
        }
        com operator*(const com&t)const{
            return {x * t.x - y * t.y, x * t.y + y * t.x};
        }
    };

    static constexpr double PI = acos(-1);
    vector<com>A, B;
    vector<int>R;
    int la, lb, mi;

    FFT(int nn = 0, int mm = 0, int N = 1) {
        la = nn, lb = mm;
        A.resize(N), B.resize(N), R.resize(N);
        mi = 0;
    }

    void update() {
        for(mi = 1; mi <= la + lb; mi <<= 1);
    }

    void init(int nn, int mm) {
        la = nn, lb = mm;
        update();
        if((int)A.size() < mi) A.resize(mi);
        if((int)B.size() < mi) B.resize(mi);
        if((int)R.size() < mi) R.resize(mi);
        for(int i = 0; i < mi; i++) {
            A[i] = {0, 0};
            B[i] = {0, 0};
        }
    }

    void fun(int op, int ab) {
        vector<com>&C = (ab == 1 ? A : B);
        for(int i = 0; i < mi; i++) {
            R[i] = R[i >> 1] >> 1 | ((i & 1) ? (mi >> 1) : 0);
        }
        for(int i = 0; i < mi; i++) {
            if(i < R[i]) swap(C[i], C[R[i]]);
        }
        for(int len = 2; len <= mi; len <<= 1) {
            com w1 = {cos(2 * PI / len), sin(2 * PI / len) * op};
            for(int j = 0; j < mi; j += len) {
                com wk = {1, 0};
                for(int k = j; k < j + len / 2; k++) {
                    com x = C[k], y = C[k + len / 2] * wk;
                    C[k] = x + y;
                    C[k + len / 2] = x - y;
                    wk = wk * w1;
                }
            }
        }
    }

    vector<i64>multiply(const vector<i64>&a, const vector<i64>&b, int lim) {
        if(a.empty() || b.empty()) {
            return {};
        }

        init((int)a.size() - 1, (int)b.size() - 1);

        for(int i = 0; i < (int)a.size(); i++) {
            A[i].x = (double)a[i];
        }
        for(int i = 0; i < (int)b.size(); i++) {
            B[i].x = (double)b[i];
        }

        fun(1, 1), fun(1, 2);
        for(int i = 0; i < mi; i++) {
            A[i] = A[i] * B[i];
        }
        fun(-1, 1);

        int len = min(lim + 1, (int)a.size() + (int)b.size() - 1);
        vector<i64>res(len);
        for(int i = 0; i < len; i++) {
            res[i] = (i64)llround(A[i].x / mi);
        }
        return res;
    }
}fft;

void solve() {
    int d;
    cin >> n >> d;
    d--;

    vector<vector<int>>to(n + 1);
    for(int i = 1; i < n; i++) {
        int u, v;
        cin >> u >> v;
        to[u].push_back(v);
        to[v].push_back(u);
    }

    i64 res = 0;

    for(int rt = 1; rt <= n; rt++) {
        vector<i64>pre1(d + 1), pre2(d + 1);

        for(auto v : to[rt]) {
            vector<i64>depCnt(d + 1);

            auto dfs = [&](auto&&self, int u, int fa, int dep)->void{
                if(dep > d) {
                    return;
                }

                depCnt[dep]++;

                for(auto nxt : to[u]) {
                    if(nxt == fa) {
                        continue;
                    }
                    self(self, nxt, u, dep + 1);
                }
            };

            dfs(dfs, v, rt, 1);

            for(int x = 1; x < d; x++) {
                if(!depCnt[x]) {
                    continue;
                }
                res += depCnt[x] * pre1[d - x];
                res += depCnt[x] * pre2[d - x];
            }

            bool ok1 = false, ok2 = false;
            for(int x = 1; x <= d; x++) {
                if(depCnt[x]) ok1 = true;
                if(pre1[x]) ok2 = true;
            }

            if(ok1 && ok2) {
                vector<i64>tmp = fft.multiply(depCnt, pre1, d);
                for(int x = 0; x < (int)tmp.size(); x++) {
                    pre2[x] += tmp[x];
                }
            }

            for(int x = 1; x <= d; x++) {
                pre1[x] += depCnt[x];
            }
        }
    }

    cout << res << '\n';
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    for(cin >> T; T--; solve());
    return 0;
}
```

## 原因

它难点不在 FFT 本身，而在于：

1. 要先看出“三点最小连通子树”只有链 / Y 两种形态；
2. 要想到枚举中心点 `rt`；
3. 要设计出：
   - `pre1`
   - `pre2`
   - `depCnt`
   这样的状态；
4. 还要进一步发现 `pre2` 的转移是卷积，能用 FFT 优化。
- **计数 + FFT 优化题**
